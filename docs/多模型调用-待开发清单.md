> 日期：2026-11-05

---

## 〇、关键技术事实（实锤）

1. **`generateQuietPrompt` 无 `profile` 参数**，签名固定 `{quietPrompt, quietToLoud, skipWIAN, quietImage, quietName, responseLength, forceChId, jsonSchema, removeReasoning, trimToSentence}`。
2. **下拉切换 profile ≠ 多模型同时可用**：切换只是 `applyConnectionProfile`（执行 `/api`、`/model` 等斜杠命令改当前配置），只有当前选中的那一个处于连接状态，其它 profile 未连接。
3. **正解：`context.ConnectionManagerRequestService.sendRequest(profileId, prompt, maxTokens, custom, overridePayload)`**
   - 位置：`SillyTavern.getContext().ConnectionManagerRequestService`（st-context.js:294 暴露，源自 `extensions/shared.js`）。
   - **不依赖当前连接状态**，只要 profile 存在于 `connectionManager.profiles`（有合法 api/api-url/model/secret-id）就能按 profileId 直接发请求，天然支持并发 + 中断。
   - 返回 `ExtractedData`（`{content, reasoning}`），非流式 `extractData=true` 时 `content` 即正文。
   - 配套方法：`getSupportedProfiles()`、`getProfile(id)`、`getProfileIcon(id)`、`validateProfile()`。

## 四、关键风险与注意点

1. **profileId 为 null 必须走 generateQuietPrompt 兜底**：不能给 `sendRequest` 传 null（会抛「Profile not found」）。
2. **返回结构是 `{content, reasoning}` 不是 `{text}`**：`llmGenerate` 里已按 `result.content` 优先、兼容字符串/`{text}`/`message.content` 多种形态。
3. **profile id 与 name 区分**：UI 用 name 展示、用 id 存值。
4. **`sendRequest` 依赖 connection-manager 扩展未禁用**：若被禁用会抛错，`llmGenerate` 已 catch 并兜底。
5. **静默调用不污染对话**：`sendRequest` 直接打 API，不写入 chat；`generateQuietPrompt` 已源码实证不污染聊天记录。
6. **`toastr` 全局可用**：前端已有 25 处使用，绑定保存反馈用它。
